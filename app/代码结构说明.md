# WeXposedHook Java 代码结构

Xposed 模块源码:挂住 WeXposed(微X模块)把功能 dex 解密进内存的时机,接管其授权校验入口。
纯 `IXposedHookZygoteInit`,无 Activity / Service。

## 工程结构

```
WeXposedHook/
├── build.gradle                  # AGP 9.4.1(需 Gradle 9.6.0+)
├── settings.gradle               # google() + mavenCentral()
├── gradle/wrapper/               # Gradle wrapper
├── local.properties              # sdk.dir=<本机 Android SDK>(勿提交)
└── app/
    ├── build.gradle              # compileSdk 37、minSdk 26、namespace github.shadowbaby.wechatxposed.hook
    └── src/
        ├── libs/XposedBridgeAPI-89.jar  # compileOnly(Xposed 官方 API 89,运行时由 LSPosed 提供)
        └── main/
            ├── AndroidManifest.xml  # xposedmodule / xposeddescription / xposedminversion / xposedscope
            ├── assets/xposed_init   # 内容:github.shadowbaby.wechatxposed.hook.XposedInit
            ├── assets/wx6_2.44.zip  # 内置载荷:功能包目录的 30 个文件(随仓库入库)
            ├── res/                 # mipmap/logo.png + values/strings.xml + public.xml
            └── java/github/shadowbaby/wechatxposed/hook/
                ├── XposedInit.java                      # 入口(IXposedHookZygoteInit + IXposedHookLoadPackage)
                ├── deploy/ModuleApk.java                # 模块自己 APK 的 assets 读取(内置载荷)
                ├── deploy/FeaturePackRestorer.java      # 30 个功能包文件的自检与补写
                ├── deploy/StartupCheck.java             # 启动自检:功能包 + 授权库
                ├── loader/WxComponentRegistry.java      # 待挂钩组件列表(WX_COMPONENTS)
                ├── loader/ModuleLogger.java             # 日志
                ├── loader/InMemoryDexLoadHook.java      # InMemoryDexClassLoader 构造 hook
                ├── loader/CurrentAccount.java           # 记住微X 传来的登录账号
                ├── license/LicenseData.java             # 账号对应的 10 行授权数据(含三层加密的第一层)
                ├── license/LicenseDatabase.java         # 把那 10 行写进 FKZ_WX_DATA
                ├── license/LicenseInstaller.java        # 按账号补齐授权库
                ├── support/WxComponentHooks.java        # 单 dex hook 注入器
                ├── support/CallMethodBypassHook.java    # 核心:CallMethod 授权伪造
                ├── support/VerifierMethodReplacement.java  # 固定返回值替换
                ├── support/HostVersionSpoof.java        # 小程序宿主版本伪装(辅助功能)
                ├── support/DexStrings.java              # 精简 dex 解析器(按字符串常量反查类)
```

产物:`app/build/outputs/apk/release/app-release.apk`。签名:本地 IDE 走 Generate Signed APK 选发行密钥库;CI 走环境变量,两者都未提供时回退 debug 签名。

## 命名约定

- 入口类 `XposedInit` 直接放在 `hook` 下,其余按职责分包:`loader`(dex 加载拦截与识别)、
  `license`(授权库生成与写入)、`deploy`(内置载荷与启动自检)、`support`(对目标 dex 的 hook 实现)。
- 字段直接用语义名(`WX_COMPONENTS` / `mode` / `componentId` / `bypassMode` / `hostClassLoader` 等);
  字符串常量集中在各类顶部,不散落在方法体里。
- 微X自身混淆过的类名(如 `c. َˉ.ᴖˉ`)按 `\uXXXX` 转义写在常量里,避免编码依赖;
  这些名字只作为字符串传给 `findClass`,与 Java 包名无关。
- 这些名字必须用**点号**分隔(`ʾⁱ.ⁱʽ`)。dex 描述符里的斜杠形式(`Lʾⁱ/ⁱʽ;`)直接交给
  `Class.forName` 会抛 `ClassNotFoundException`,类名对了也解析不出来;`tests/dex-probe/` 专门钉这条。

## 类职责

| 类 | 职责 | 涉及的关键字符串 |
|---|---|---|
| `XposedInit` | 入口:initZygote 挂 `InMemoryDexClassLoader` 构造并记下模块 APK 路径;handleLoadPackage 在微信主进程跑启动自检、在主进程与小程序进程挂宿主版本伪装 | `dalvik.system.InMemoryDexClassLoader` / `com.tencent.mm` / `com.tencent.mm:appbrand0` / `com.tencent.mm:appbrand1` |
| `InMemoryDexLoadHook` | afterHookedMethod 识别四个组件 dex(componentId 0=Base / 1=Core / 2=Themes / 3=Donation);beforeHookedMethod 屏蔽 5 个校验入口 | 四个组件入口类名与日志文案;`disable` / `on_update_check` / `process_metadata` / `updateLicense` / `delayed_check` |
| `ModuleLogger` | 日志输出(正文一律英文、精炼) | 日志前缀 `WeXposedHook-> ` |
| `WxComponentHooks` | 对单个组件 dex 的 ClassLoader 注入 hook:Core 挂 6 个;Base / Themes / Donation 只挂入口做握手 | `com.fkzhang.wechatxposedhooks.WxJniCoreBridge` / `CallMethod` 及各自的入口类与方法名 |
| `CurrentAccount` | 记住微X 每次校验传来的登录账号,并让启动自检按它补一次授权库 | `wxid_` |
| `LicenseData` | 按账号生成 FKZ_WX_DATA 的 10 行:第一层 AES-256-CBC(零 IV/PKCS7) + Base64,LIC 第 3 段用 SHA-256(账号) 现算;另提供判断库里已有值能不能用的解密/还原 | `31d019ea...` / `LIC:` / `verifier6#D:` / `[1]` |
| `LicenseDatabase` | 建表/补齐 10 行并把 user_version 置为 1;已经是该账号的 LIC/verifier6 原样保留;写前备份 .bak | `FKZ_WX_DATA` / `DATA` / `android_metadata` |
| `LicenseInstaller` | 按账号写入/补齐 `databases/FKZ_WX_DATA`;同一个账号只写一次,失败不记、下次再试 | `license db: ` / `created` / `existing` |
| `ModuleApk` | 按 `StartupParam.modulePath` 读模块自己 APK 的 assets(模块是独立 APK,读不了微信的 assets);路径失效时按包名重找 | `assets/wx6_2.44.zip` |
| `FeaturePackRestorer` | 30 个功能包文件的文件级自检与补写;文件名是内容指纹,大小不符也算缺失 | 30 个文件名与字节数(见源码清单) |
| `StartupCheck` | 启动自检入口:定 `dataDir`、补功能包、从 prefs 读登录账号递给 `LicenseInstaller` | `login_weixin_username` |
| `CallMethodBypassHook` | **核心**:拦截 `WxJniCoreBridge.CallMethod` 与授权查询,按 `bypassMode` 分流(0=校验拦截、1=授权上下文、2=透传);`afterHookedMethod` 处理 `wxid_` 前缀 | `verifier6` / `param` / `LIC` / `8.0.49` / `true` / `unlimited` / `remote_rp_cmd` / `#` + 58 项功能列表;`wxid_` |
| `VerifierMethodReplacement` | 把轮询校验、接口请求、更新提示整体替换为固定返回值 | `blocked polling verifier` / `blocked check api` / `blocked update tips` |
| `HostVersionSpoof` | 小程序宿主版本伪装:构造器第 7 个参数(libVersion)改 9999;private_openUrl 里指向官方升级页的 URL 清空。类名混淆,按字符串常量反查 | `MicroMsg.AppBrand.CgiLaunchWxaApp|func:1122` / `<init> cgiHash[%d], ... libVersion[%d], ...` / `private_openUrl` / `geta8key_open_webview_appid` / `open_custom_style_url` / `https://support.weixin.qq.com/update` |
| `DexStrings` | 精简 dex 解析器:按 header 固定偏移读 string/type/proto/method/class 表,扫方法字节码里的 const-string,给出「含某组字符串的类」。零第三方依赖 | 无(纯格式解析) |
| `DexPaths` | 从微信 base.apk 里按 zip 条目读出 classes*.dex 的字节,直接交给 `DexStrings`(不落盘) | `classes` / `.dex` |

## 运行时流程

1. `XposedInit.initZygote` 挂 `dalvik.system.InMemoryDexClassLoader` 的全部构造函数,
   并记下模块 APK 路径(`ModuleApk.remember`)——内置载荷在那里面。
2. 每次有 dex 通过内存构造器加载,`InMemoryDexLoadHook` 在当前 ClassLoader 里
   `findClassIfExists` 四个组件入口类,命中即调 `WxComponentHooks.inject` 并从待办列表移除。
3. Core 组件注入的 hook 里,`CallMethodBypassHook` 按 `msgId`(130/132/150)与查询类型
   伪造校验结果与功能列表,`VerifierMethodReplacement` 堵掉三处在线校验入口。
4. Base / Themes / Donation 只挂入口方法做握手,命中 `disable` 等 5 个方法名时返回 null 屏蔽。
5. 微信主进程启动时,`XposedInit.handleLoadPackage` 调 `StartupCheck.run`:
   `FeaturePackRestorer` 先按清单看 `files/wx6_2.44` 里 30 个文件齐不齐,缺哪个就从内置载荷补写;
   `LicenseInstaller` 再按微信 prefs 里的登录账号补一次授权库。
6. 微X 校验授权时把权威账号交给 hook(`CurrentAccount.remember`),启动自检据此再补一次库
   (同一个账号只写一次);补完重启微X 生效。
7. 微信主进程与小程序进程(`:appbrand0` / `:appbrand1`)启动时,`HostVersionSpoof.install`
   用 `DexPaths` 取出 base.apk 里的 dex,交给 `DexStrings` 按字符串常量反查两个混淆类
   (启动构造器所在类、private_openUrl 所在类),再挂 hook。每个进程只挂一次。

第 7 步是**辅助功能**:它跑在启动自检之后,`install` 内部吞掉所有异常,`XposedInit`
外面再兜一层,所以它失败不影响第 1–6 步的主功能。

## 字符串池对照

`docs/StringPools.java` 保存各类字符串常量的池原文与「偏移 / 长度 / key / 明文」对照表。
该文件在 app 的 sourceSet 之外,**不参与编译、不打进 APK**(APK 的 classes.dex 里
`StringPools` / `*_POOL` 字样计数为 0)。可直接运行复核:

```
java docs/StringPools.java
```

## 构建

需要 JDK 17 与 Android SDK 37(AGP 9.4.1 要求 Gradle 9.6+):

```powershell
JAVA_HOME=<JDK17> ./gradlew assembleRelease
```

> 内置载荷随仓库入库:`app/src/main/assets/wx6_2.44.zip` 里是功能包目录的 30 个文件,
> 构建时原样打进 assets(约 3.0 MB),不需要额外脚本。

release 构建开着 R8(`minifyEnabled true`)。这对本模块是安全的,但**改动类结构/回调时
必须复核 `app/proguard-rules.pro` 的保留规则**,否则入口会被改掉:

- `assets/xposed_init` 里的类名由框架按字符串加载,`XposedInit` 必须保留原名。
- `XC_MethodHook` / `XC_MethodReplacement` 的 `beforeHookedMethod` / `afterHookedMethod` /
  `replaceHookedMethod` 由框架反射调用,规则里按方法签名 `-keepclassmembers` 保留
  (公开入口例外,会由 `-keep class XposedInit` 覆盖)。
- 微X 的类名(含 `c. َˉ.ᴖˉ` 这类)以字符串传给 `findClass`,与 R8 无关,不受影响。

验证方法:构建后对 `classes.dex` 跑 `dexdump -f`,确认
`Lgithub/shadowbaby/wechatxposed/hook/XposedInit;` 的 `initZygote` 以及各 hook 类的
`beforeHookedMethod` / `afterHookedMethod` / `replaceHookedMethod` 都在。
