# WxModuleHook Java 代码结构

Xposed 模块源码:挂住 WeXposed(微X模块)把功能 dex 解密进内存的时机,接管其授权校验入口。
纯 `IXposedHookZygoteInit`,无 Activity / Service。

## 工程结构

```
WxModuleHook/
├── build.gradle                  # AGP 9.4.1(需 Gradle 9.6.0+)
├── settings.gradle               # google() + mavenCentral()
├── gradle/wrapper/               # Gradle wrapper
├── local.properties              # sdk.dir=<本机 Android SDK>(勿提交)
└── app/
    ├── build.gradle              # compileSdk 36、minSdk 26、namespace github.shadowbaby.wechatxposed.hook
    └── src/
        ├── libs/XposedBridgeAPI-89.jar  # compileOnly(Xposed 官方 API 89,运行时由 LSPosed 提供)
        └── main/
            ├── AndroidManifest.xml  # xposedmodule / xposeddescription / xposedminversion / xposedscope
            ├── assets/xposed_init   # 内容:github.shadowbaby.wechatxposed.hook.XposedInit
            ├── res/                 # mipmap/logo.png + values/strings.xml + public.xml
            └── java/github/shadowbaby/wechatxposed/hook/
                ├── XposedInit.java                      # 入口(IXposedHookZygoteInit)
                └── rebuild/
                    ├── annotation/KeepForDex.java       # 编译期注解(运行时未引用)
                    ├── loader/WxComponentRegistry.java  # 待挂钩组件列表(WX_COMPONENTS)
                    ├── loader/ModuleLogger.java         # 日志 + 微信目录定位
                    ├── loader/InMemoryDexLoadHook.java  # InMemoryDexClassLoader 构造 hook
                    ├── support/WxComponentHooks.java    # 单 dex hook 注入器
                    ├── support/CallMethodBypassHook.java    # 核心:CallMethod 授权伪造

```

产物:`app/build/outputs/apk/release/app-release.apk`(签名 `data/release.keystore`)。

## 命名约定

- `rebuild` 下按职责分包:`annotation`(编译期注解)、`loader`(dex 加载拦截与识别)、
  `support`(对目标 dex 的 hook 实现)。
- 字段直接用语义名(`WX_COMPONENTS` / `mode` / `componentId` / `bypassMode` / `hostClassLoader` 等);
  字符串常量集中在各类顶部,不散落在方法体里。
- 微X自身混淆过的类名(如 `c. َˉ.ᴖˉ`)按 `\uXXXX` 转义写在常量里,避免编码依赖;
  这些名字只作为字符串传给 `findClass`,与 Java 包名无关。

## 类职责

| 类 | 职责 | 涉及的关键字符串 |
|---|---|---|
| `XposedInit` | IXposedHookZygoteInit 入口,挂 `InMemoryDexClassLoader` 构造 | `dalvik.system.InMemoryDexClassLoader` |
| `InMemoryDexLoadHook` | afterHookedMethod 识别四个组件 dex(componentId 0=Base / 1=Core / 2=Themes / 3=Donation);beforeHookedMethod 屏蔽 5 个校验入口 | 四个组件入口类名与日志文案;`disable` / `on_update_check` / `process_metadata` / `updateLicense` / `delayed_check` |
| `ModuleLogger` | 日志输出 + 微信进程/目录定位 | `android.app.ActivityThread` / `currentActivityThread` / `getSystemContext` / `com.tencent.mm` / `_wx_`;日志前缀 `WxModuleHook-> ` |
| `WxComponentHooks` | 对单个组件 dex 的 ClassLoader 注入 hook:Core 挂 6 个,Base/Themes/Donation 只挂入口做握手 | `com.fkzhang.wechatxposedhooks.WxJniCoreBridge` / `CallMethod` 及各自的入口类与方法名 |
| `CallMethodBypassHook` | **核心**:拦截 `WxJniCoreBridge.CallMethod` 与授权查询,按 `bypassMode` 分流(0=校验拦截、1=授权上下文、2=透传);`afterHookedMethod` 处理 `wxid_` 前缀 | `verifier6` / `param` / `LIC` / `8.0.49` / `true` / `unlimited` / `remote_rp_cmd` / `#` + 58 项功能列表;`wxid_` |
| `VerifierMethodReplacement` | 把轮询校验、接口请求、更新提示整体替换为固定返回值 | `banned polling verifier` / `banned check api request` / `banned updated tips` |

## 运行时流程

1. `XposedInit.initZygote` 挂 `dalvik.system.InMemoryDexClassLoader` 的全部构造函数。
2. 每次有 dex 通过内存构造器加载,`InMemoryDexLoadHook` 在当前 ClassLoader 里
   `findClassIfExists` 四个组件入口类,命中即调 `WxComponentHooks.inject` 并从待办列表移除。
3. Core 组件注入的 hook 里,`CallMethodBypassHook` 按 `msgId`(130/132/150)与查询类型
   伪造校验结果与功能列表,`VerifierMethodReplacement` 堵掉三处在线校验入口。
4. Base / Themes / Donation 只挂入口方法做握手,命中 `disable` 等 5 个方法名时返回 null 屏蔽。

## 字符串池对照

`docs/StringPools.java` 保存各类字符串常量的池原文与「偏移 / 长度 / key / 明文」对照表。
该文件在 app 的 sourceSet 之外,**不参与编译、不打进 APK**(APK 的 classes.dex 里
`StringPools` / `*_POOL` 字样计数为 0)。可直接运行复核:

```
java docs/StringPools.java
```

## 构建

需要 JDK 17 与 Android SDK 36(AGP 9.4.1 要求 Gradle 9.6+):

```powershell
JAVA_HOME=<JDK17> ./gradlew assembleRelease
```
